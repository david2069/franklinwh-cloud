PRIMARY FINDING — invalidates the shipped preflight rule
  Throughout the hour:
    4GNetSwitch        = 1     (cellular enabled)
    operatorRSSI       = 21-22 (modem registered, has signal)
    4GConnectBSStatus  = 0     (not carrying traffic)
    WifiSignalStrength = 78-80 (WiFi healthy)

  So cellular is AVAILABLE but IDLE — the aGate parks the transports it is
  not using. get_network_state() derives 'link' from 4GConnectBSStatus, so
  it classifies an available modem as unlinked, and linked_transports will
  essentially always hold exactly one entry.

  Consequence: the preflight rule set(linked_transports) - {target} refuses
  EVERY write to the transport currently carrying traffic. Right now that
  blocks the primary use case, even though 4G is demonstrably ready to take
  over — it did exactly that in the 2026-03-21 incident and again this
  morning. The rule must key on ENABLED + CAPABLE, not CURRENTLY LINKED.
